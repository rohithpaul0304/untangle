# Untangle Play Designer

Coordinate an independent team that creates interesting things to do, not only catchy things to read. This skill adapts selected MIT game-design and narrative workflows for Codex. Read [adaptation.md](references/adaptation.md) for sources and boundaries.

## Dispatch modes

The root coordinator alone launches Designers A/B/C. A worker assigned one designer role enters single-designer mode: produce exactly one candidate, do not launch other designers, do not inspect other candidates. The coordination instructions below apply only to the root coordinating the comparison.

## Design

For an opening comparison, use three independent designer agents producing one candidate each unless the user specifies otherwise. All receive the same brief and prior corrections, but not each other's drafts or a coordinator-selected favorite. The coordinator handles integration and testing, not all three designs. Do not call three passes by one agent an independent team. If separate workers are unavailable, report that limitation rather than quietly substituting one author. Each should be a short complete choice → consequence → discovery sequence, with a second move that can use the discovery. Target about one minute of play, but label this a target until timed with people.

When the Teacher supplies a checked brief, all three designers must preserve its learning objective, prerequisites and factual model. Choose the interaction independently. Only explore different concepts when the user explicitly requests topic exploration; label that comparison as different whole experiences, not a test isolating interaction style. Vary what the player DOES, not just setting or nouns. Examples: configure a rule and observe its effects; commit a scarce resource and replay an alternative; inspect a user's behavior and change a product. Do not copy these examples as mandatory genres.

For each candidate deliver a complete branch script plus a separate learner-only pre-choice file with stable scene IDs and no outcomes, key or author commentary. Coordinator supplies sequential portions to a fresh Answer Checker for the early interpretation check before Writer expansion.

For each candidate write:
- Exact first screen: role, event, immediate goal, clear controls and essential constraints. No unexplained terminology.
- Exact visible rules and initial state, including quantities and what the player can change.
- Every first-choice branch, its visible consequence and conversational fox response. No unexplained scene jump.
- Discovery and visible concept name; one second move applying it under a changed condition.
- Complete results of that second move, plus a natural stopping point.
- One reason to continue, and one concrete risk that could make it boring.

Design backward from the intended feeling (curiosity, agency, earned insight) to player behavior and rules. The action should still offer an interesting challenge without XP, coins awarded as praise, or mascot decoration. A prediction can be interesting but must not be graded on hidden facts. Declared fictional rules must determine outcomes consistently; never choose payoffs afterward to make the learner wrong. Use visible quantities for state, not decorative fake stakes.

Different viable paths are useful; do not force every decision to be ambiguous. Objective puzzles can have a correct answer if the goal and rules justify it. Avoid repeated 'obviously prudent' versus 'careless' choices. A failed move should reveal useful information and allow a targeted correction without restarting.

## Test and revise

After all designers finish, use a separate reviewer who did not write candidates. Preserve drafts before review, then revise only defects supported by findings. Report independent generation and subsequent revision separately. Test logic and interpretation before expanding. Give a fresh reviewer learner-facing screens without author intentions or answer keys first. Ask what role, goal, controls and result they infer. Save their first interpretation, then compare the model/key. Label it simulated review, never a human test.

If independent drafts converge on the same mechanic, preserve that finding and request bounded diversity revisions without sharing other drafts. Distinguish independent first generation from later coordinator constraints.

Clarify what a pre-action preview reveals. Do not promise discovery while showing the complete outcome before the move. If a learner finishes after an unsuccessful second move, provide a worked successful outcome or explicitly label it a pause; do not leave the intended solution unexplained.

Trace every branch numerically where relevant; compare action counts, points of uncertainty, redundant taps and whether choices change state. Name concrete defects, revise, and recheck affected branches. Recommend a candidate with reasons and unresolved risks; do not invent a fun score or declare a winner proven.

For motion/feel review, inspect a playable build or detailed video. Inspect action → visible response → consequence → settled state, hierarchy, timing, replay and reduced-motion state. A script permits a motion plan, not verified latency or animation quality. Do not import universal timing, audio or retention claims from upstream templates.

## Deliver

Save a concise comparison, full branch scripts, independent review record and a small uncoached human-test protocol under `content-team/play-openings/` (or a user-specified location). Include a view with only learner screens so the user need not read author notes. Mark imagined enjoyment, observed software behavior and human evidence separately. Stop at the requested opening scope; no full chapter, production prototype edits or deployment unless requested.

Hand the selected opening to the existing content team for accurate explanation, objective answer checking and targeted practice. Adding this role does not certify autonomous course production.
