# Untangle quality contract

Plain language, serious reasoning. Aim for useful work insights, not obvious advice with coins attached. Earn curiosity without hiding decisive rules or fabricating surprising results.

One focused screen per beat. Respond, then transition. Visual movement explains cause; fox gestures support it. Do not stack more text beneath an unchanged scene. Prefer short dialogue, concrete nouns and small numbers where scale is irrelevant. Show a named concept after its mechanism, then a fresh application.

Approved voice anchor: “Your customers pay you five coins. Your ad costs two. That leaves you three.” Why it worked: familiar role already established; text follows the visible movement; a single causal chain; no new rival or rule introduced mid-calculation.

Rejected patterns: “Which change should we test first?” as a forced lesson-navigation choice; company A/B introduced without context; explanations longer than the action; arbitrary payoffs revealed only after grading; animations that jiggle without explaining; blank praise after a wrong response.

Every scored question needs a checked answer, reason each alternative fails, and misconception tag. Never infer a learner's motive from one click. Route to targeted feedback and a fresh question, then back; after another failure show a worked example with pause/revisit. Do not call one correct answer mastery.

Review gates: evidence checked; definitions before grading; answers independently solved; all branches exist; visual counts match numbers; no text beyond learner's knowledge; action changes meaningful state; new scenario tests transfer. Keep gate statuses separate from human comprehension and engagement, both untested until measured.

Learner test: show without live coaching; ask what changed and why, then give a fresh problem. Record confusion verbatim. A correct guess or agent approval alone does not demonstrate understanding. Do not alter locked approved project content while piloting a different topic.

For proportional diagrams, label normalized rates as rates; never depict a selected sample as though it were the original data. Define time origin and observation boundary before scoring time-window questions. Repeating an item whose solution has been shown is supported practice, not fresh assessment evidence. Count meaningful choices separately from navigation taps.

Independent-answer review must receive question-only input without inline feedback. A separate answer-key file is insufficient if the storyboard itself prints correct explanations beneath the options. Preserve the first solve before comparing keys; be honest if the reviewer saw solutions.
