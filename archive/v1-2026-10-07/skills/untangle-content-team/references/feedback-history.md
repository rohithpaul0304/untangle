# Corrections that define this team

Source: founder conversation and project memory.md / STORY-WRITING.md, reviewed 7 October 2026. This is an authoring contract based on feedback, not measured engagement evidence. Later explicit approvals supersede earlier rejection notes.

| Founder feedback / observed failure | Required authoring check | Reviewer |
|---|---|---|
| “I'm not able to understand the flow” on the first screen | Introduce role, event and meaningful question before diagrams or a conclusion. Essential context belongs in the guide, not tiny supporting text. | Editor |
| “I still didn't understand B” | Introduce rival or relationship before names, quantities or consequences involving them. | Editor |
| “When I selected ... there was no explanation” | Every branch acknowledges that selection and explains the next event before switching setting/time. Never invent the player's reasoning. | Writer + editor |
| “What do you want to test first ... I don't want things like this” | Choices concern the story, not which explanation to open or experiment to watch. | Editor |
| “Why is the 20 and 15 again?” | One current state per object. Clearly distinguish a selectable price from money earned; avoid several meanings for one number. | Checker + editor |
| “Too long ... not conversational” | Short direct fox speech; necessary context retained. Do not turn one sentence into each of 26 mandatory taps. Count actual taps and decisions. | Editor |
| “Visualisations ... without reading the text ... intuitive” | Describe concrete before→movement→after. All displayed counts reconcile. No ledger standing in for a causal event. | Writer + checker |
| Text said customers switched while both groups stayed unchanged | Every claimed state change must be visible. Payments follow customers; money does not teleport between companies. | Checker |
| “Green box ... not helpful ... chat-based” | Feedback addresses the actual answer and explains the result through the fox and scene change. Generic praise is insufficient. | Writer |
| “On every response ... new screen ... adding ... bottom” | Replace the current beat with consequence view, preserve familiar objects, then transition. No endless appended blocks. | Editor |
| “Character ... static ... jiggle ... hands” | Fox expressions and purposeful gestures respond to events. Compact size, both hands when useful, intact proportions; reduced-motion still states. | Writer |
| “Concept name should be seen ... what did you learn” | Show mechanism, then visible concept name and plain definition, then a fresh application. | PM Teacher |
| “Very simple ... no takeaway ... work” | Require a useful inference the learner can use at work. Plain words do not justify trivial reasoning. | PM Teacher + editor |
| “Did professor teach this way?” / missing McKinsey and book | Maintain source coverage and limitations. Never attribute invented stories to unread lectures; keep citations internal. | Researcher |

| “More surprising examples alone won't prevent boredom” | Vary central activity, retain strongest stories, avoid repeating the same choice/explanation rhythm. | PM Teacher |
| “Correct answer ... says correct ... chapter-wise” | Explicit objective answer feedback; possible misconception leads to reviewed fresh practice and return, not chapter restart. Strategy tradeoffs are not universal truths. | Checker |
